# UK Wheat Yield Forecasting Pipeline

This repository contains the data and code behind a comparative study of forecasting methods for UK wheat yield. The full account is the thesis *Comparative Analysis of Machine Learning and Time-Series Models for Precision Agricultural Forecasting*.

The project compares eight models on the national yield series from 1980 to 2024 (45 observations): a persistence baseline, ARIMA, SARIMA, ARIMAX, Prophet, Random Forest, XGBoost, and a two-stage ARIMA+XGBoost hybrid. Every model runs under identical expanding-window cross-validation over four forecast horizons, so the differences in the results reflect the models themselves rather than differences in how they were set up or tested.

The pipeline is organised into five stages, from raw data through to the final comparison, and the whole thing runs from a single notebook, `uk_wheat_pipeline_full.ipynb`. The raw weather files, the modelling table, and the canonical outputs that results are checked against are all committed here. A run therefore needs no network access, and the reported numbers can be regenerated by anyone with a Python environment.

## How the results are produced

| Stage | Purpose |
|---|---|
| 01 Data Acquisition | Downloads the Met Office UK climate series, or reuses the frozen copies in `data/raw/` |
| 02 Modelling Table | Combines weather, yield, and policy indicators into a single table |
| 03 EDA | Exploratory analysis of the series and its covariates |
| 04 Feature Engineering | Builds the model-ready features and the exogenous forecasts |
| 05 Model | Runs the cross-validation, significance tests, prediction-interval evaluation, the oracle experiment, and the final verification |

Stage 05 ends with a verification step. Every produced number is compared against the canonical values in `data/expected/`, and the run prints `ALL CHECKS PASSED` only when they match. This is what makes the thesis numbers independently checkable rather than a matter of trust.

## Running it

The simplest option is Google Colab. Open the notebook below and choose Runtime → Run all.

> [Open in Colab](https://colab.research.google.com/github/Dickuta/msc-uk-wheat-forecast/blob/master/uk_wheat_pipeline_full.ipynb)

The setup cells clone the repository into the Colab environment, install the pinned dependencies (the runtime restarts once so the pinned numpy loads cleanly), and then run the five stages in order. A standard Colab CPU runtime takes roughly 10 to 20 minutes, most of it in stage 05.

To run locally, clone the repository and open the notebook in Jupyter or VSCode. The setup cells detect that the notebook is already inside a clone, skip the download, and check the packages in your kernel against the versions pinned in `requirements.txt`, installing anything that is missing or out of sync. The notebook also works if you are given just the file itself: on the first run it clones the repository next to the notebook, or into a temporary directory when the location is read-only.

If you prefer the command line, each stage is a standalone script under `stages/` (for example `python stages/05_Model.py`), and `main.py` runs the stages in sequence.

## Dependencies

`requirements.txt` pins the exact package versions that produced the thesis numbers. The same pins are mirrored in `pyproject.toml`, so `pip install -e .` installs the same set. The main packages are numpy 2.5.1, pandas 3.0.5, scikit-learn 1.9, statsmodels 0.14.6, prophet 1.3, and xgboost 3.4.

## Data

Weather comes from the Met Office UK Climate Series, an observation-based product derived from the HadUK-Grid 1 km dataset, used under the Open Government Licence. Stage 01 downloads it, or reuses the frozen copies in `data/raw/` when they are already present. Yield figures are the DEFRA national series, and the policy indicators (1992 CAP reform, 2005 Single Payment Scheme, 2022 input shock) are constructed binary dummies.

One point of provenance is worth stating plainly. The thesis numbers rely on a warmer, England-focused weather extraction that cannot be rebuilt from the public UK-mean series. The pipeline keeps that extraction as the source of record and quantifies its difference from the UK-mean rebuild, so the choice is documented rather than hidden.

## A note on the numbers

Two things are worth knowing before trusting the output.

First, the machine-learning models are tuned once over the full series, which means the selected hyperparameters see years that later become test years. Their errors are therefore slightly optimistic relative to the statistical models, which select their structure from training data only. The study discloses this rather than correcting it, because changing the tuning would move every machine-learning result and the pipeline was built to reproduce the original work faithfully.

Second, `data/expected/` was regenerated from the corrected pipeline on 2026-08-06, after the refactor fixed an ARIMAX covariate-selection bug in the thesis code. The ARIMAX figures change by roughly 0.006 t/ha in RMSE and 0.009 t/ha in MAE. The original thesis numbers are preserved in `data/thesis_reference/`, together with a ledger of every difference. `ALL CHECKS PASSED` therefore certifies that this pipeline reproduces its own verified results; it does not re-certify the un-corrected thesis numbers themselves.

The verification schema was extended on 2026-08-08 with Diebold–Mariano tests on both MSE and MAE loss (including a per-horizon Bonferroni flag), prediction-interval coverage and interval scores for the four models that produce native intervals, and Augmented Dickey-Fuller diagnostics in stage 03. These were pure additions: no RMSE or MAE point estimate changed.
